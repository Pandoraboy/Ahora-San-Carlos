# Guía de trabajo

## Flujo recomendado

1. Crear una rama desde `develop`.
2. Trabajar en una tarea concreta.
3. Probar el cambio.
4. Actualizar documentación cuando corresponda.
5. Crear un commit descriptivo.
6. Integrar el cambio mediante pull request.

## Ramas

```text
main
develop
feature/nombre-funcionalidad
fix/nombre-correccion
docs/nombre-documentacion
```

## Convención de commits

```text
feat: nueva funcionalidad
fix: corrección
docs: documentación
test: pruebas
refactor: mejora interna
chore: configuración o mantenimiento
```

## Criterio de avance terminado

Una tarea se considera terminada cuando:

- Su objetivo está claro.
- El código funciona.
- Los errores previsibles están controlados.
- Existe una prueba o evidencia.
- La documentación fue actualizada.
